# 데일리 뉴스 생성 복구 변경 검토 — 2026-11-09

운영 배포 전 검토용. 시장지표 수집(fetch_data.py), 시장 마감일 계산, 72시간 뉴스 기간 및 출처 날짜 검증은 유지한다.

## 원인과 변경

11/9 로그는 후보 57건과 세 번의 JSON 형식 실패를 기록한다. 원본 AI 응답/stop_reason은 저장되지 않아 원인을 pause_turn 또는 max_tokens로 단정하지 않는다.

1. API: pause_turn에서 assistant content를 그대로 이어 보내며 최대 두 번 이어받는다. max_tokens는 잘린 결과를 버리고 같은 요청을 12000 토큰으로 한 번 확장한다. 전송/이어받기/확장을 합쳐 call_api당 HTTP 요청 최대 6회. 비복구 HTTP 실패도 SystemExit 대신 대체 경로로 처리한다. 형식 복구는 검색 없이 기존 응답을 구조화하고, 출처·날짜 검증 실패는 다른 원문을 검색한다. stop_reason, 출력 토큰, 검색 횟수·오류를 로그로 남긴다.
2. 대체 선정: AI 호출 없음. CNBC/BBC/MarketWatch 글로벌 후보와 연합뉴스 국내 후보를 분리한다. 전시회·수출상담·렌터카·생활 판결·사건사고·개인 생활금융 사례를 먼저 제외한다. 핵심 시장어 4점, 변화/발표 단서 2점, 일반어 최대 2점. 핵심어 두 종류 또는 핵심어+사건 단서를 필수로 하고 최소 6점. 관련성 점수 → 발행시각 순. 정규화 URL과 같은 언어 제목 유사도(0.78)로 중복 제거. 기준 미달은 비워 두며 영문 RSS 본문은 표시하지 않는다. 원문 제목은 영문으로 남을 수 있다.
3. RSS: 기존 CNBC Top News를 Finance로 교체하고 Economy와 MarketWatch Breaking News를 추가했다. 각 채널의 실제 XML 제목과 파싱 성공을 확인했다. BBC/연합뉴스 유지. 피드별 최대 30건을 관련성 우선으로 확보한다. 피드가 삭제한 과거 기사를 복원하는 보관 시스템은 아니며, 72시간을 넘겨 날짜를 늘리지 않는다.
4. 상태: 정상/일부 제공/생성 실패 배지, 뉴스가 없으면 확정 문구와 시장지표 버튼. 일부·실패 상태의 OG 설명은 주요 뉴스라는 표현을 쓰지 않는다. 알림 제목·본문과 report.json에도 상태를 전달한다. 원문 제목만 있는 대체 카드도 일부 제공으로 처리한다.
5. 08:00 KST 복구: 같은 날 비정상 상태만 대상. workflow_dispatch의 recovery 입력도 제공한다. 전역 workflow concurrency 아래에서 .state/news-recovery.json에 당일 시도를 먼저 커밋하므로 실패하더라도 같은 날 자동 복구를 다시 실행하지 않는다. 정상 상태는 생략. 기존 수동 실행은 가능하다. GitHub 예약 작업은 실제 시작이 지연될 수 있다.
6. 원본 응답·후보 스냅샷은 gitignore된 debug/news/ 아래에만 저장하며 Actions artifact로 7일 보관한다. docs/에는 원본 응답을 넣지 않는다. 테스트 fixture는 언론사 RSS 후보이며 AI 원본 응답이 아니다.

## 실행 시간 예산

- 빌드 잡: 기존 15분 유지.
- 최초 단계에서 885초 후를 내부 마감으로 기록한다(15초 여유).
- 생성 시간 = min(540초, 내부 마감까지 남은 시간 - 180초), 음수이면 0초.
- 생성 하위 프로세스에 RSS 수집, 검색, 이어받기, 모든 재시도와 쉬운 말 다듬기를 포함한다.
- 하위 프로세스의 벽시계 시간이 끝나면 강제 종료하고 후보 스냅샷으로 규칙 기반 대체를 만든다. 프로세스 종료 회수 대기는 최대 5초이며 대체 계산/파일 저장은 로컬 작업이다.
- 선택적 AI 분류 호출은 도입하지 않았다. 대체 결과에 대한 쉬운 말 AI 호출도 생략한다.
- 시간 제한이 없다면 명목 요청 타임아웃 합은 최대 3 × (6 × 90초 + 3초 backoff) + 다듬기 184초 + 병렬 RSS 8초 ≈ 30분 21초다. requests timeout은 전체 벽시계 상한이 아니므로 이 합에만 의존하지 않는다.
- 실제 운영 생성 상한은 9분 + 종료 회수 최대 5초 + 짧은 로컬 대체 작업이며, 앞 단계가 오래 걸리면 더 줄어든다. 초기 설치/시세 수집 자체의 실패나 렌더링/배포 인프라 장애까지 성공을 보장하는 변경은 아니다.
